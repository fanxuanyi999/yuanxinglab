# 一单一码：首版使用说明

## 本地运行

使用 Node 24.14 或以上版本。在项目 `.env.local` 中设置 `VITE_ACCESS_REQUIRED=true`，重启 Vite。
分别打开两个终端运行 `npm run dev:access` 和 `npm run dev`。

首页公开，开始测试或恢复历史答题/报告前检查兑换凭证。输入错误或服务不可用时不会放行。凭证使用 HttpOnly Cookie 保存 30 天，过期后重新输入原兑换码即可。答题进度仍保存在当前浏览器，换浏览器不会同步答案。

## 发码

确认订单已付款后执行：

```powershell
npm run code:issue -- "小红书订单号"
npm run code:issue -- "小红书订单号" literature
```

把测试网址和独立的 6 位兑换码发给客户，客户点击开始后手动输入。所有购买同一测试的客户使用相同网址，但兑换码不同；补发同一订单、同一测试返回原码。保留前导零，已有 8 位码和长码迁移为历史人格专用码，仍可手动输入。旧的全站登录凭证失效，需要重新兑换。

实际部署兑换服务后，设置 `$env:ACCESS_PUBLIC_URL='https://1108.work'`，命令按测试自动输出 `/yuanxinglab/`、`/literature/`、`/creator/` 或 `/career/`。默认测试为 yuanxinglab，其他测试标识作为第二个参数。其余测试目前只是后端预留标识，不代表对应产品已经开发或部署。未配置时仍输出本地预览地址，不可发给客户。

链接不再包含兑换码。旧链接的 `#code=...` 和 `?code=...` 不会自动兑换或填入表单。兑换码和会话均由服务端绑定测试；历史人格的码和 Cookie 都不能访问文学测试。未来各测试前端须调用自己对应的 `/api/access/<测试标识>/session` 与 `/redeem`，并为答题记录设置独立 localStorage 键，避免同域名不同产品的进度混用。

本版允许同一码重新进入、重新测试及在其他设备使用，不做设备绑定、次数限制或统计。所以客户转发兑换码后，其他人也能使用。这是本阶段明确接受的限制。

## 数据与部署

- 数据默认保存在当前系统用户目录 `.yuanxinglab/access.sqlite`，不在网页或仓库目录内。发码命令和服务必须使用同一系统用户及数据库。可用服务端环境变量 `ACCESS_DB_PATH` 指定外部绝对路径，不能放到 public、dist 或 Vite 项目目录中。
- 数据库包含订单及可补发的兑换码，应妥善保管。备份时先停止服务和发码操作，再复制整个 `.yuanxinglab` 目录；恢复到同一路径。多实例部署不在本版范围内。
- API 默认仅监听 `127.0.0.1:8787`；Vite 将同源 `/api` 请求代理过去。正式部署需持久化磁盘的 Node 服务，并通过 HTTPS 同源反向代理 `/api`，设置 `NODE_ENV=production` 以启用 Secure Cookie。构建时设置 `VITE_ACCESS_REQUIRED=true`。
- GitHub Pages 只能托管静态页面，不能运行本服务。当前实现仅在本地验证，正式启用付费入口前需要安排服务托管；不得仅上传前端就当作可上线的兑换系统。
- 1108.work 的 DNS/自定义域名不自动提供 API；仍需让 `https://1108.work/api/access/...` 代理到兑换服务。同源代理是当前实现的部署前提，不能直接把 GitHub Pages 当 API 服务。本次未修改 DNS、仓库或线上部署。
- 没有管理后台、公开发码接口或小红书订单连接。命令不验证支付状态，需卖家确认付款；自动发货需以后接入选定的平台/工具。
- 本版是基础入口校验，评分和报告仍在前端运行，不能防止有技术能力的人复制公开代码或绕过前端。没有更改现有评分和报告内容。
- `VITE_ACCESS_REQUIRED=false` 可用于公开演示，不适用于付费部署。没有默认万能兑换码。

## 验证

`npm test` 包含兑换码持久性、订单唯一性、重复兑换、非法码与 Cookie/API 校验；`npm run build` 检查前端构建。
