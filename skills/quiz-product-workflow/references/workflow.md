# 从主题到可分享测试：完整工作流

这是一套娱乐与自我探索类测试的产品开发方法，来自历史人格 MVP 的实际研究、实现、修订与上线。它复用流程和工程骨架，不宣称能复制销量或为新主题提供已验证的心理量表。

阅读路线：首次开发按 1–10 推进；换主题重点看 2–5；视觉迭代看 6；发布看 9；完整例子见 [主题适配](theme-adapters.md)。

## 1. 研究需求与交付，不只看竞品首页

先写清：谁在什么情境点开、想知道什么、愿意完成多少题、看到什么会觉得被理解、愿意分享哪一部分。区分满足好奇、身份共鸣、行动参考和关系不确定感。

研究可访问的竞品时走完整旅程：入口承诺 → 开始门槛 → 作答 → 改答/刷新 → 结果 → 分享 → 返回。保存关键屏幕与观察时间，并区分“页面看到”“实际操作验证”“推断”“未知”。不同选择路径用于观察结果差异，不复制竞品题库与报告。

商业信息另记：标价、单品销量、店铺销量、交付承诺、支付后实际交付是否验证。当前标价乘累计销量不等于真实营收，销量截图也不证明新项目需求。研究记录不直接进入公开代码仓库，避免带入访问码、分享令牌或私人信息。

产出：一页产品简报和证据索引。没有研究条件也可以做 MVP，但把需求假设与已知事实分开。只在本次确需当前价格、平台规则或新来源时做实时核查。

## 2. 先决定结果模式与差异

| 用户的问题 | 合适的输出 | 推荐模式 |
|---|---|---|
| 我像哪个人物？ | 一个主意象、相邻侧面、具体共鸣 | 原型匹配 |
| 我偏好怎样的工作/发挥方式？ | 多维偏好、适合环境、尝试建议 | 偏好画像，可附主类型 |
| TA 的互动意味着什么？ | 可观察信号、替代解释、信息缺口 | 证据分流，不做读心概率 |
| 我的生活心态是什么样？ | 不同情境的节奏/倾向 | 多轴画像或娱乐性标签 |
| 我有哪些值得培养的倾向？ | 有行为证据的优势线索与小实验 | 优势探索，不认证天赋 |

结果设计先于大规模出题。为每个候选结果写一张卡：核心动机、典型行为、资源与代价、与最接近结果的区别、适用边界、主视觉、分享句。两个结果只差名字时，先合并或重写差异，不靠增加标签凑数量。

历史项目的 24 人、8 维、72 题、每轮 30 题、13 章不是通用标准。新项目可先用 6–12 个结果、4–6 个明确维度、12–20 道固定题试做；这些是起步建议，不是质量门槛。固定题更易校准，只有确有重测需求时再引入题库随机抽样。

产出：结果目录、模式选择理由、维度定义（两端含义、可观察行为、容易混淆的概念）、近邻结果区分表。

## 3. 用结果反推题目，先跑小闭环

先做少量能区分典型结果的题和一份完整报告，接通结果计算、图片和分享。验证这种主题是否有实际的阅读价值，再扩充题库、报告和美术资产。

每题记录：稳定 ID、场景类别、观察维度、提问、选项 ID、权重或证据标签、设计理由、可能歧义、编辑状态。最终用户只看问题与选项。

题目写具体情境，不问“你是否优秀/有领导力”。选项各有收益与代价，长度与语气接近，避免一项明显正确；不把能力、意愿、资源条件混为一谈。一题观察一项主要取舍，可附少量相关维度，但不是每个主题都必须多维赋权。避免通过同义改写人为扩容。

“不知道”和“不适用”采用显式标记，不能塞进普通负权重选项。关系观察题尤其要区分“不知道对方是否这样做”与“确认没有发生”。记录时间窗口与情境，避免把一次偶然事件写成稳定模式。

若使用随机题库：按维度、情境和必要证据分层抽取；持久化随机种子、题目顺序、选项顺序。对每个维度检查可取得的分值范围，不只检查题数；重要判别题不能被随机抽掉后仍给出同样确定的结论。

产出：原创题库、内容/覆盖矩阵、人工试答记录。试答者要能用自己的话解释问题与选项；分歧反馈用于改题，而不是简单归为“用户没理解”。

## 4. 选择可检查的计算规则

### 原型匹配

先得到用户维度画像，再与结果画像比较。若沿用本项目的每轮理论范围归一化：

```text
raw[d] = Σ 已选选项的权重[d]
lo[d]  = Σ 本轮每题所有合法选项在 d 上的最小权重
hi[d]  = Σ 本轮每题所有合法选项在 d 上的最大权重
profile[d] = 100 × (raw[d] - lo[d]) / (hi[d] - lo[d])
```

未提及维度按 0 处理。缺失作答先校验；hi=lo 说明无区分信息，应明确该维度不可解释，或采用记录在案的工程兜底，不能写成用户天生均衡。“不知道”不参与此公式，除非已定义缺失值策略与有效覆盖要求。

这不是把某个人最高项强制拉到 100、最低项拉到 0，也不是人群百分位。若用标准化欧氏距离、维度权重或相似度曲线，写清依据、参数与同分处理，不设“至少 88%”之类伪精确保底。展示接近度是可选项；通常标签与具体理由已足够。

隐藏/第二原型是可选功能。只在确有近邻候选且能写出有证据的补充侧面时显示；若差异弱，承认相近，不制造“表面与内心完全相反”的戏剧冲突。

### 偏好画像

输出各轴倾向及其组合，不把所有人压成一个职业或天赋标签。区分喜欢做、经常做、做得好、具备机会四类证据。不同轴可能同时高或低；均衡与情境依赖要有自己的报告。

### 互动证据分流

把观察完整度与信号方向分开。先检查有效观察量、持续性和矛盾，再输出“信息不足”“存在主动接近信号”“互动主要依赖具体情境”等分支。阈值属于产品规则，需用例检验和用户试读；没有标注样本与校准时不显示喜欢概率。

### 共同验证

- 相同有效题目与答案产生相同结果；选项位置变化不改变含义。
- 修改旧答案从最终答案集合重新计算，不在旧总分上继续累加。
- 每种宣称可达的结果保留一组合法答案见证；无法命中的结果先修规则或缩小结果集。
- 模拟检查输出偏置、近邻塌缩、改一两题的变化和抽题变化。预算依规模决定，不盲目固定十万次。
- 随机结果不必均匀，也不能靠给稀有结果配额修饰分布。
- 分支型产品覆盖未知、冲突、边界和反例；无需为了沿用历史模板跑人物距离模拟。
- 模型、题库含义变化升级版本，并决定旧记录迁移或提示重答；仅改叙事不应悄悄改变结果。

产出：规则说明、可运行计算、测试、分布/分支报告和答案见证。工程通过不等于科学信效度通过。

## 5. 把计算结果写成一份“对你说”的报告

报告是一条阅读路径：揭晓 → 产生共鸣 → 看见具体行为 → 理解张力 → 得到温和可做的下一步。章节数量按主题和移动端阅读长度取舍。

可复用章节槽位：主标题、相逢理由/观察结论、三个侧面、资源、可能的消耗、关系方式、工作/行动方式、情境故事、补充侧面、组合收束、一个小行动、真实答案回看、分享入口。不是每款产品都需要所有槽位；暗恋主题应替换为观察、替代解释与沟通建议。

内容分三层：

1. 结果专属内容：独有意象、动机与张力，避免 24 份只是换名字。
2. 按画像条件选择的片段：强、弱、均衡、冲突时语气不同；不能把相对第一写成杰出能力。
3. 真实答案线索：只引用用户实际选过的内容，不编造经历、童年或他人的心理。

反例：“本轮探索得分相对靠前，因此匹配李白。”

改写：“你常愿意为一个新念头偏离原来的路线。未知会让你犹豫，也会让你想亲自走近看看。”只有答案支持时才使用这段。

默认正文不讲阈值、排名、生成过程。方法、史料出处、图表读法放入轻量说明入口；开关后恢复焦点和阅读位置。产品承诺本身要诚实，例如“这些互动值得留意”优于“TA 暗恋你 92%”，不能把后一种误导藏在弹窗解释。

历史和文学内容区分事实、出处、版本差异与原创想象；原创比喻不伪造为名言。优势旁边有真实代价，但不羞辱、不贴病理标签。涉及实际职业建议或专业心理结论时，另行补充相应研究与专业校核，不从娱乐模型直接升级。

验收每个结果、边界画像与合法组合。组合文本覆盖与实际可达组合分开统计。

## 6. 统一美术与阅读层级

先拆参考：人物画法、配色、材质、字体层级、布局与动效分别记录。借鉴人物画法不等于复刻页面。实际打开参考图，而不是只读文件名。

制作结果视觉清单：ID、轮廓、姿态、道具、主题色、构图安全区、源提示词、参考来源、生成工具、原文件和网页文件路径、验收状态。先做一张代表图，检查风格与网页适配，再批量生成；失败按人物定向重做。

透明素材检查真实 Alpha、边缘白边、道具截断、衣摆和安全空间；不要接受画出来的棋盘格。原图保留，网页图按统一画布与安全区导出。用整套联系表比较差异性，不能仅同一身体换颜色。

首页缩略图、列表、报告大图、分享海报四处一起验收。为长姓名、超长标题、宽道具和深浅主题留出空间。字体可自托管并检查授权；主题资源路径遵循构建 base，不写死网站根目录。

东方插画是历史产品的选择，不是职业或关系测试的默认风格。按新主题决定插画、抽象场景或轻量图形是否更合适。

## 7. 复用工程骨架，隔离主题数据

现有历史项目不是已经完成的多主题引擎。第二个主题先复制必要模块，出现稳定共性后再抽象，避免提前重写整个项目。

推荐边界（目标结构，需按项目落地）：

```text
应用外壳：导航、答题、进度、恢复、错误反馈、报告容器、分享
主题包：文案、维度、题库、结果目录、图片、报告章节和配色
模式适配器：校验、抽题、计分/证据整理、结果选择、报告数据
基础服务：存储、事件、资源地址、可选的订单权益
```

共享接口以明确契约为准：`validateAnswers`、`selectQuestions`、`evaluate`、`buildReport`、`buildShareData`。不同模式的结果对象用带 `mode` 的联合类型，不强迫暗恋主题拥有 character.vector。

会话至少包含 themeId、schemaVersion、modelVersion、questionSetVersion、seed/题序、optionOrders、answers、currentIndex、stage。按主题隔离存储键；同名题 ID 不能跨主题误恢复。版本冲突或损坏数据给出重新开始入口；存储不可用仍能完成当前内存会话。

建议页面状态：首页 → 可选权益验证 → 答题 → 结果整理 → 报告 → 分享预览。处理连点锁定、返回改答、刷新、未完成直达结果、重测确认、加载失败和减少动态效果。整理动画只做节奏，不谎称调用了在线 AI。

MVP 可使用确定性本地规则与预写内容，不必增加模型服务、账户或支付。前端环境变量、演示访问码和 localStorage 都不是生产鉴权；付费交付需要单独设计服务端权益。

## 8. 分享卡是独立交付物

先决定用户愿意展示什么，不把整份长报告截成长图。通常保留品牌、结果名、主视觉、少量标签、一句原创表达与真实回流入口；关系类默认不放姓名、聊天原文和隐私答案。

独立绘制布局，等待字体与图像加载；测量文字、保留长名字空间，确保同源/CORS 支持导出。历史项目采用 1080×1440 PNG，可按平台调整。

桌面下载、移动端系统分享、长按保存分别处理。系统分享应在用户点击事件中发起；取消不等于故障，预览不因失败消失；关闭后回收对象 URL。不能生成假二维码或把占位框描述成可扫码入口。

验证实际导出文件的尺寸、可解码性、字体、人物、边缘与空白。浏览器下载事件不代表相册保存成功；模拟手机不等于真机或平台内置浏览器验收。

## 9. 按风险验收并单独发布

| 层级 | 关键验收 | 证据 |
|---|---|---|
| 内容 | 原创、语境、事实来源、结果差异、边界结论 | 编辑记录、试读反馈 |
| 模型 | 确定性、有效输入、可达性/分支、扰动 | 测试结果、合法答案见证 |
| 状态 | 返回、刷新、连点、重测、损坏/旧版本 | 实际操作记录 |
| 页面 | 所有结果、窄屏/桌面、长名字、弹窗 | 截图与溢出/错误检查 |
| 分享 | 图像加载、导出文件、取消和降级 | PNG 与设备范围 |
| 构建 | 干净依赖安装、测试、生产构建、子路径 | 命令与输出摘要 |
| 线上 | 部署结果、真实页面、资源、一次正常答题与分享 | URL、提交号、浏览器证据 |

只改文档无需重跑全站；权重变更重跑模型与代表流程；共享布局或字体变更覆盖全结果；仅某图重做验证该图四处引用和透明度。任何未跑项标记“未验证”，不把工具故障写成通过。

本地验证后提供预览和具体变更。遵循当前用户发布授权；默认本地优先、确认后再推送和部署。上传仓库不等于上线。GitHub Pages 项目站需正确 base，动态图片地址、字体、图标、分享图都验证子路径；工作流只部署构建目录。未来发布采用手动触发，除非用户选择自动发布。

Pages 的具体操作与 Actions 版本可能变化，实施时核对官方文档。工具缺权限或故障时说清卡在哪一步，给出最短可完成操作；不要把历史环境故障变成永久限制。

## 10. 交接与下一轮验证

交付产品简报、主题数据、规则与内容文档、素材清单、验收记录、运行方式、版本号和未完成项。把工程已通过与用户是否喜欢分开：记录开始率、完成率、哪题退出、报告读完、分享请求和实际回流；只统计已取得必要授权的数据，默认不上传原始答案。

下一轮先验证一个具体假设，如“减少歧义能否降低第 7 题退出”，避免同时大改题库、结果和视觉导致无法判断原因。不保证完测率、分享率或销量；用实际试读与行为反馈修订。
